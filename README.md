# Gmail 重複メール検出・自動ゴミ箱移動

同じ日に、同じ件名・同じ本文・同じ送信者で届いたメールを重複とみなし、
最も古い1通を残して残りを自動でゴミ箱へ移動する Google Apps Script (GAS) です。

## 仕組み

- `src/Code.gs` の `findAndTrashDuplicateEmails()` が、直近 `CONFIG.LOOKBACK_DAYS` 日間の
  受信トレイを検索します。
- メールごとに「日付（yyyy-MM-dd）＋件名（正規化済み）＋本文のハッシュ値＋送信者」を
  キーとしてグループ化し、同じキーが2件以上あれば重複と判定します。
- 重複グループの中で最も古い1通だけを残し、残りをゴミ箱へ移動します。
- 重複メッセージが他の非重複メッセージと同じスレッドに属している場合は、
  スレッドごとの削除による巻き添えを避けるため自動処理せず、ログに
  「手動確認要」として記録します。

## セットアップ手順

1. [script.google.com](https://script.google.com/) で新しい Apps Script プロジェクトを作成する
   （または `clasp create` で作成し、このリポジトリを push する）。
2. `appsscript.json` の内容をプロジェクトのマニフェストに反映する。
3. `src/Code.gs` の内容をスクリプトエディタにコピーする。
4. まずは安全確認のため `CONFIG.DRY_RUN = true` にした状態で
   `findAndTrashDuplicateEmails` を手動実行し、初回の権限承認を行う。
5. 実行ログ（表示 > ログ）で、ゴミ箱へ移動される予定のメール一覧を確認する。
   問題なければ `CONFIG.DRY_RUN = false` に戻す。
6. `createDailyTrigger` を一度だけ手動実行すると、毎日 6:00（`Asia/Tokyo`）に
   自動実行されるトリガーが設置される。

## 設定項目（`CONFIG`）

| 項目 | 説明 |
| --- | --- |
| `LOOKBACK_DAYS` | 何日前までのメールを検索対象にするか |
| `SEARCH_QUERY` | Gmail 検索演算子で対象を絞り込む（例: `-in:chats` で除外） |
| `DRY_RUN` | `true` の場合、削除せずログ出力のみ行う |
| `REQUIRE_SAME_SENDER` | 同一送信者からのメールのみ重複とみなすか |
| `NOTIFY_EMAIL` | 実行結果をメールで通知したい場合に指定 |
| `PAGE_SIZE` / `MAX_THREADS` | 検索時のページングと安全上限 |

## 注意事項

- Apps Script の `GmailMessage.moveToTrash()` はメッセージが属する
  スレッド全体をゴミ箱へ移動する仕様のため、このスクリプトは
  重複メッセージが単独スレッド（1メッセージのみ）である場合にのみ
  自動でゴミ箱へ移動します。スレッドに他のやり取りが含まれる場合は
  安全のためスキップされ、ログに記録されます。
- 誤検知が心配な場合は、まず `DRY_RUN = true` で数日運用し、
  ログの内容を確認してから自動削除を有効にすることを推奨します。
- ゴミ箱に移動したメールは Gmail 側の設定（通常30日）で自動的に完全削除されます。
  誤って削除した場合はゴミ箱から元に戻せます。

# ニュース収集・整理（`src/NewsCollector.gs`）

「対象」シートで選んだカテゴリ × 言語 × 検索クエリごとに Google ニュースの RSS から
記事を集め、重複を除いて「記事」シートへ蓄積し、カテゴリ・言語別に整理した
ダイジェストを1日2回メールで送ります。日本語以外の見出しには日本語訳を付けます。

初期設定の対象は **ウクライナ情勢** で、**戦況 / 外交・停戦交渉 / 支援・各国の動き** の3カテゴリ ×
**日本語・英語・中国語・韓国語・ロシア語・ウクライナ語** の18通りです。
一般的な政治・国際情勢・軍事の行も無効の状態で入っているので、チェックすれば併用できます。

## セットアップ手順

1. `src/NewsCollector.gs` を同じ Apps Script プロジェクトに追加する（別プロジェクトでも可）。
2. `setupNewsCollector` を一度手動実行し、権限を承認する。
   「ニュースまとめ: ウクライナ情勢」スプレッドシートが作成され、URL が実行ログに出力されます。
3. スプレッドシートの「対象」シートで、集めたい対象を選ぶ・編集する。
   - **有効**: チェックを外すとその行は収集しない
   - **カテゴリ**: 自由に命名可（メールではこの単位で見出しが分かれる）
   - **言語**: `ja` / `en` / `zh`（簡体）/ `zh-TW`（繁体）/ `ko` / `ru` / `uk`
   - **検索クエリ**: Google ニュースの検索構文（`OR`、`"完全一致"`、`-除外語`）が使える
   - 行を追加すれば対象を増やせます（特定の国・人物・兵器名などで絞り込みも可能）
4. `collectNews` を手動実行して、メールと「記事」シートの内容を確認する。
5. `createNewsTriggers` を一度だけ手動実行すると、毎日 7:00 と 18:00（`Asia/Tokyo`）に
   自動実行されるトリガーが設置されます。

## 設定項目（`NEWS_CONFIG`）

| 項目 | 説明 |
| --- | --- |
| `TITLE` | スプレッドシート名とメール件名に使うタイトル |
| `SPREADSHEET_ID` | 既存のスプレッドシートを使う場合に指定（空なら自動作成） |
| `NOTIFY_EMAIL` | ダイジェストの送信先（空なら実行ユーザー自身） |
| `LOOKBACK_HOURS` | 何時間前までに公開された記事を対象にするか |
| `MAX_ITEMS_PER_QUERY` | 1クエリあたりの最大取得件数 |
| `MAX_ITEMS_PER_GROUP_IN_MAIL` | メールに載せる1グループあたりの最大件数（シートには全件残る） |
| `TRANSLATE_TITLES` | 日本語以外の見出しを日本語訳するか |
| `RUN_HOURS` | 実行時刻（変更後は `createNewsTriggers` を再実行） |
| `SEND_EMPTY_DIGEST` | 新着0件でもメールを送るか |

## 注意事項

- 一度記録した記事（見出しを正規化したもの）は次回以降の実行で除外されるため、
  同じ記事が朝と夕方の両方に載ることはありません。複数媒体が同じ見出しで配信した場合も1件にまとまります。
- 見出しの翻訳には Apps Script の `LanguageApp` を使っており、1日の呼び出し回数に上限があります。
  上限に達した場合は訳なしで記録・送信されます。
- Google ニュースの RSS は非公式の提供形態のため、仕様変更で取得できなくなる可能性があります。
